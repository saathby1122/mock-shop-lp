# mock.shop landing page

Static build of the new mock.shop landing page ("Sample Stores for Building With AI") from the Figma desktop
export. Plain HTML, CSS and vanilla JavaScript, no build step, hosted on GitHub Pages.

- Live: https://saathby1122.github.io/mock-shop-lp/
- Source of truth for the design: `reference/mockup-desktop.png` (1440 x 6529) and `reference/mockup-hero.png`
  (the hero and the Start / Build / Test steps now follow Kyu Kim's animated designs instead: `HERO.md`, `FLOW.md`)
- What was measured and decided: `SPEC.md`
- Open questions and placeholders: `TODO.md`

## Files

| Path | What it is |
| --- | --- |

## Working on it

Serve the folder with any static server (`python3 -m http.server`), or open `index.html` directly: from `file://`
the flow runs, but the hero stays its static picture (module scripts cannot load from `file://`) and the console
shows four CORS errors for it. Assets are referenced relatively so the page works from a sub-path.

To turn on the live storefront preview instead of the static screenshot, set `data-live="true"` on the
storefront preview container in `index.html` (see `TODO.md` for why it is off).

## Deploying

Pushing to `main` publishes the root of the repository through GitHub Pages (`.nojekyll` keeps Jekyll out of the
way). No build step. The files only the Rails landing's re-sync reads (`hero/MANIFEST.sha256`, `flow/assets.txt`,
`flow/markup.html`, `flow/MANIFEST.sha256`, `flow-icons/`) are published with the rest; no page links to them, and
`flow/markup.html` is a fragment of `index.html`, not a page (opened on its own, its relative links miss). The Rails
landing records the commit it last re-synced from, so land a commit it takes on `main` as it is (a fast-forward, not
a squash or a rebase) and that commit stays one anyone can fetch.
